Findings from E2E audit
Coverage gap

A caregiver-mode grandparent (holding a temporary-approver grant) passes the authorization check for Accept/Decline, but has no UI to use it — ParentReviewDeck.tsx, their only review screen, has zero GP-offer cards. Authorized but dead-ended.

Minor

If the authorization guard fails, Accept/Decline silently no-ops with only a console warning — no Alert or toast tells the parent why nothing happened.

Minor

Accept/decline outcome only reaches the offering GP via an unpushed in-app chat DM, unlike the offer itself which sends a real push — inconsistent with how other approve/decline outcomes notify elsewhere in the app.

Needs live test

No DB-level conditional-update (unlike approveChore's explicit CAS pattern) guards claimGPErrand — two grandparents offering at the exact same moment is a theoretical race not provable by static reading alone.

Teen Quest Reward Co-Sign Threshold

A teen can self-create a quest with any reward. If the total (base + bonus) exceeds a household-set threshold, the coin payout is held for parent sign-off — the task itself is unaffected and fully workable.

Findings from E2E audit
Confirmed bug — fixed

The threshold check originally read only base coins — bonus coins were applied via a separate, later updateQuest call that ran after the threshold check had already passed. A teen could bypass the entire gate by putting most of the reward in the bonus field. ✓ Fixed — bonusCoins now included in the initial addQuest payload, verified by follow-up audit.

Gap

The teen gets zero visibility that their reward is under review — no indicator at creation, and the quest card looks identical to a fully-paid one even after work is approved.

Findings from E2E audit
Confirmed bug — fixed

The auto-complete branch hardcoded payout to the gpCoins wallet regardless of quest type, while every other payout site in the file selects the wallet from categoryType === 'grandparent_quest' || sponsorUserId. A plain (non-sponsored) errand should pay mainCoins — the kid's real spendable balance, split across Spend/Save/Give. ✓ Fixed — now uses the identical formula as every other payout site, verified by follow-up audit.

Verified correct

The rewardPendingReview guard is correctly mirrored on the auto-complete path — a teen's flagged reward still can't be paid out through this route, no double-pay or bypass risk.
