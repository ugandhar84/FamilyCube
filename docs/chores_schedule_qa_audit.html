Part 3

Confirmed Bugs

Both found this pass are the same failure mode: a store action invokes quest-event-notifier with an event name the edge function's switch statement doesn't recognize — it silently falls to default and nothing is ever delivered.

Low–Medium

cheerChore fires a dead notification event

choreStore.ts:1973 invokes event: 'chore_cheered'. quest-event-notifier/index.ts:118-257 has no matching case.

Repro: a grandparent or sibling cheers a completed chore. The coin-award side effect still works (separate call), but the "someone cheered you!" push never fires.
Low–Medium

appreciationPing fires a dead notification event

choreStore.ts:3078 invokes event: 'appreciation_ping' — same silent no-op via default.

Repro: a parent sends an appreciation ping on a completed delegated quest. It likely still lands as an in-app chat DM via a separate path, but never arrives as a push notification.

Recommended fix (not applied): add case 'chore_cheered': and case 'appreciation_ping': to the notifier's switch, mirroring the existing gp_offer_pending pattern.
