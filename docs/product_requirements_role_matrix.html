Family Cube — Product Requirements

Role-Based Behavior Matrix
for Chores, Quests & Calendar Events

This document defines, from first principles, the ideal target behavior of Family Cube for every household role — independent of any existing implementation. For each realistic family-coordination scenario, it specifies exactly what each role should see on their own screen, exactly what actions should be available to them at that moment, and the product reasoning for why that is the correct behavior for a real family. This is a requirements specification, written as if defining the product before any code exists.

Roles covered: Parent-1, Parent-2 (a household may have one or more parents), Kid, Teen, and Senior/GP (grandparent or other senior caregiver). Role labels are used generically throughout — no scenario hardcodes a specific person's name to a specific role, because in a real family any member could occupy any of these roles.

PENDING Something is waiting on a decision — awaiting approval, awaiting claim, awaiting RSVP. Time-sensitive, needs attention.
BLOCKED / DECLINED A negative or terminal state — declined, rejected, cancelled, removed, or an action that is explicitly disallowed for this role.
INFORMATIONAL A read-only, passive view — the role can see this but has no action to take on it right now.
ACTION AVAILABLE An actionable control is present — used inline before bolded action-button labels to flag "this role can act here."
NOTIFIED This role receives a push/badge notification for this event, distinct from someone who must passively discover it.
HIDDEN / NOT VISIBLE This item does not appear at all on this role's screen — an intentional visibility/privacy boundary, not a bug.
