Family Cube — Code Audit

Requirements vs. Code — Gap Audit

docs/product_requirements_role_matrix.html defines 65 target-behavior scenarios from first principles, written without reading any implementation. This document is the other half of that pair: it diffs each of those 65 scenarios against the actual current code — store/choreStore.ts, store/eventStore.ts, store/choreAdapter.ts, store/familyStore.ts, store/kidRequestStore.ts, store/rewardStore.ts, store/notifStore.ts, and the corresponding Hub/Quests/Calendar UI — and records what actually happens today, citing file and line for every claim.

Confirmed bugs found during this pass were fixed directly in the same working tree and are marked GAP — FIXED below with a short note on the change. A small number of confirmed, reachable bugs were found but not fixed this pass — usually because the safe fix wasn't small/contained, or the fix depends on a larger missing piece — these are marked GAP — CONFIRMED BUG. Gaps that require a genuinely new feature (new UI, new data model, new permission concept) were not built — building them silently, without a deliberate product decision, was explicitly out of scope for this pass — and are marked GAP — MISSING FEATURE with the reasoning for why they weren't attempted. Scenario 1.12b is the one item the requirements doc itself flags as an intentional future capability the app does not support today; it is marked N/A and excluded from the gap counts. A few findings could not be confirmed without live multi-device testing; those are marked UNCONFIRMED alongside their primary verdict rather than asserted as fact.

Every claim in this document is backed by an actual file:line citation from reading the real code — nothing here is inferred or assumed. Where certainty required live/multi-device testing that wasn't performed, that limitation is stated explicitly rather than silently asserted as fact.
